# tiny-ecosystem — 小さな生態系

ブラウザの中の小さな森で、植物・草食・肉食がルールだけで増え、減り、消えていく放置系シミュレーターです。
プレイヤーにできるのは「雨を降らせる」「生き物を少しだけ放す」ことくらい。
同じ seed・同じパラメータ・同じ介入なら必ず同じ展開になり、その展開は URL ひとつで共有できます。

- サーバー不要（静的ファイルのみ）、AI/LLM 不使用
- シミュレーションコア（`src/core/`）は DOM 非依存の純 TypeScript

## 使い方

```bash
npm install
npm run dev      # 開発サーバー
npm run build    # 型チェック + dist/ に静的ビルド
npm test         # Vitest（決定論・再現性・PRNG・不変条件・URL codec）
npm run bench    # シミュレーション速度の計測
npm run survey -- 300 5000   # 300 seed × 5000 tick を回して絶滅率を集計
```

`npm run survey` の第3引数にパラメータの差分 JSON を渡すと、その設定で集計できます。
例: `npm run survey -- 100 5000 '{"carnivore":{"speed":1.4}}'`

## 画面

- **ワールド**: 植物の濃淡（緑）、土の湿り具合、草食（クリーム色）、肉食（橙）。「水分を表示」で水分を青で重ねる
- **再生**: 一時停止/再生（スペースキーでも可）、速度 1x / 4x / 16x / 64x、リセット、seed 入力、🎲 でランダム seed
- **介入**: ツールを選んで盤面をクリック/タップ。クールダウンと残り回数をボタンに表示
- **個体数の推移**: 植物・草食・肉食を種ごとに独立したスケールで並べた折れ線（直近 720 tick）。0 になると「絶滅」表示
- **できごと**: 絶滅・全滅・介入のログ。絶滅はワールド上にも通知
- **プリセット / パラメータ**: プリセット切替、全パラメータの編集（適用すると同じ seed で最初から）
- **共有**: 現在の状態を URL hash に書き出してクリップボードにコピー

## ルール概要

1 tick の処理順は「(その tick の介入) → 水 → 植物 → 動物 → tick+1」です。

### 地形（水）
- 各セルは水分 0〜1 を持つ。毎 tick、4 近傍へ拡散し（盤面の端からは流出しない）、`evaporation` の割合だけ蒸発する
- 毎 tick `rainChance` の確率で、ランダムな地点に半径 `rainRadius` の自然の雨（中心ほど多い）
- 初期水分は seed から作るまだら模様（湿った所と乾いた所ができる）

### 植物（セルごとのバイオマス 0〜1）
- 水分が `growthThreshold` 以上なら成長: `growthRate × 水分 × (b + 0.15) × (1 − b)`。成長した分だけ水を使う（`waterUse`）
- 水分が足りないと `wiltRate` ずつ枯れる
- 植物のない肥沃なセルは、4 近傍のバイオマス合計 × `seedRate`（+ `sproutChance`）の確率で芽生える
- 更新はダブルバッファなので走査順の偏りはない

### 動物（個体ごとに位置・エネルギー・年齢を持つ）
毎 tick、全個体を PRNG でシャッフルした順に処理します（順序バイアスを避けつつ決定論的）。
各個体は年齢 +1、エネルギー −`metabolism`、移動 1 マスごとに −`moveCost`。
エネルギーが `reproduceThreshold` 以上になると、`reproduceShare` の割合を子に渡して隣のマスに産む（生まれた子はその tick には動かない）。
エネルギー 0 以下か `lifespan` に達すると死ぬ。盤面は壁で囲まれていて外には出られない。

- **草食**: 半径 `fleeRadius` に肉食がいれば反対方向へ逃げる。そうでなく足元の植物が少なければ、視野 `vision` 内で「バイオマス − 0.08 × 距離」が最大のセルへ向かう（なければランダムウォーク）。足元の植物を最大 `biteSize` 食べ、食べた量 × `foodEnergy` を得る。食べ尽くしはせず、根（0.03）は残る
- **肉食**: 満腹（最大の 90% 以上）でなければ、視野内で最も近い草食へ向かう。同じマスに草食がいれば `huntSuccess × (1 − hideFactor × そのマスの植物量)` の確率で捕食し `foodEnergy` を得る。つまり茂みは草食の隠れ家になる
- `speed` の小数部は「もう 1 歩進める確率」（例: 1.2 = 毎 tick 1 歩、20% の確率で 2 歩）

### 介入
| 介入 | 効果 | 制限 |
|---|---|---|
| 雨を降らせる | クリック地点を中心に半径 6 の水分 +0.7（中心ほど多い） | クールダウン 60 tick |
| 植物を植える | 半径 2 の範囲の植物を 0.6 まで増やす | 生き物の追加と合わせて 1 回の世界で 3 回まで、間隔 300 tick |
| 草食を 8 匹放す | 半径 2 の範囲に草食 8 匹 | 同上 |
| 肉食を 3 匹放す | 半径 2 の範囲に肉食 3 匹 | 同上 |

介入はすべて `(tick, 種類, x, y)` として介入ログに記録され、その tick の処理の直前に適用されます。
ライブ操作でも URL からの再生でも同じタイミングなので、結果は完全に一致します。
制限は `src/core/interventions.ts` の `RULES` にあり、ログからの再生時にも検証されます（不正なエントリは捨てる）。

## 決定論

- 乱数は `src/core/rng.ts` の mulberry32 のみ。`Math.random` は使っていません（新しい seed を選ぶときだけ UI 側で `crypto.getRandomValues` を使う）
- tick は固定ステップ。1x = 30 tick/秒で、描画フレームレートとは独立（速度を上げると 1 フレームで進める tick 数が増える）
- `hashWorld()`（FNV-1a）でワールド全体（水・植物・全個体・PRNG 状態）の指紋を取り、テストで一致を確認しています
- ブラウザの開発者コンソールで `ecosim.debugState()` を呼ぶと、現在の tick とハッシュを確認できます

## URL 形式

```
https://…/#v1.z<base64url>
          │  │└ データ本体（base64url、パディングなし）
          │  └ z = deflate-raw 圧縮した JSON / j = 非圧縮 JSON（ごく短いときはこちらの方が短い）
          └ フォーマット/ルールのバージョン
```

JSON の中身:

```jsonc
{
  "s": 30,                         // seed (uint32)
  "t": 1432,                       // 開いたときにこの tick まで早送り
  "p": { "carnivore": { "speed": 1.4 } },  // DEFAULT_PARAMS との差分のみ（なければ省略）
  "l": [[120, "r", 10, 12],        // 介入ログ [tick, 種類, x, y]
        [400, "c", 40, 8]]         //   r=雨, p=植物, h=草食, c=肉食
}
```

- 開くと初期状態から介入ログを再生し、`t` まで早送りします（進捗バー付き。数万 tick でも数秒）
- パラメータが既定値なら URL は 40 文字前後、介入が数回あっても 100 文字程度です
- ルールや既定パラメータを変えて結果が変わる場合は `src/codec/codec.ts` の `CODEC_VERSION` を上げてください。古いバージョンの URL を開くと、再現できない旨を表示します

## プリセット

| 名前 | seed | 特徴 | 40 seed での傾向（5000 tick） |
|---|---|---|---|
| いつもの森 | 30 | 既定値。捕食者・被食者の波が続き、この seed では約 4500 tick で大きく崩れる | 60% が共存、最初の絶滅の中央値 1937 tick |
| 安定する池 | 1 | 雨が多く茂みが深い。捕食者は控えめ | 72% が共存 |
| 絶滅しやすい森 | 14 | 乾いた森に俊敏な捕食者 | 共存 0%、最初の絶滅の中央値 507 tick |
| 大発生 | 2 | 豊かな草原で草食が 2000 近くまで増え、肉食も 300 超に | 共存 0%、最初の絶滅の中央値 793 tick |

## バランス（既定パラメータ、300 seed × 5000 tick）

`npm run survey -- 300 5000` の結果:

```
carnivore extinct: 53.7%  median tick 1929  [0-500:0 500-1000:23 1000-2000:60 2000-3000:21 3000-5000:57]
herbivore extinct: 45.0%  median tick 1766  [0-500:0 500-1000:33 1000-2000:46 2000-3000:14 3000-5000:42]
plant extinct:     0.0%
all coexist at end: 45.7%
peak herbivores median 638 max 977
peak carnivores median 54 max 84
```

最初の 500 tick で絶滅する seed はなく（しばらく安定）、その後は捕食者・被食者の周期的な揺らぎが続き、
約半数の seed がどこかで絶滅に至ります。草食が先に絶えると肉食も後を追います。植物は絶滅しません。

## 性能

`npm run bench`（Node 22, クラウド環境の CPU, 描画なし）:

| ケース | 個体数 | ms/tick | 1x（0.5 tick/フレーム） | 16x（8 tick/フレーム） |
|---|---|---|---|---|
| 既定 (64×64) | 約 200 | 0.16 | 0.08 ms | 1.3 ms |
| 大発生のピーク (64×64) | 約 1000 | 0.46 | 0.23 ms | 3.7 ms |
| 負荷試験: 5000 個体 (64×64) | 5000 | 1.65 | 0.83 ms | 13.2 ms |

ブラウザ（ヘッドレス Chromium、GPU なしのソフトウェア描画、1280×900）で描画込みの実測:

| ケース | 1x | 16x |
|---|---|---|
| 既定 | 60 fps | 60 fps |
| 負荷試験: 5000 個体 | 60 fps | 約 23 fps |

64×64・数千個体でも通常速度（1x）で 60fps を維持します。5000 個体で 16x にするとシミュレーション自体が 1 フレームの予算（16.7ms）を使い切るため fps が落ちます。
動物の描画は数千個の `arc()` ではなく、JS でピクセルバッファに点を打ってから 1 回で転送しています（GPU のない環境でも速い）。

```
  render/      Canvas 描画（ワールド・グラフ）、パレット

```
